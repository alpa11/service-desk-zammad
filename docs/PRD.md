# מערכת ניהול קריאות תחזוקה - אפיון פונקציונלי (PRD)

## סקירה כללית

### חזון המוצר
מערכת קלה ונעימה לניהול קריאות תחזוקה, שעובדת כמו **To-Do מקצועי** - פשוטה, זורמת, ללא מורכבות מיותרת.

### עקרונות מנחים
- **מינימום קליקים** - כל פעולה בכמה שפחות צעדים
- **מינימום שדות** - רק מה שהכרחי
- **אפס בלבול** - ממשק ברור לכל משתמש
- **המערכת משרתת את התפעול** - לא להפך
- **To-Do קודם ל-Helpdesk** - פשטות על הכל

### מה המערכת אינה
- **לא מערכת התכתבויות** - אין Chat, אין Email, אין Reply
- **לא מערכת Helpdesk מורכבת** - אין SLA, אין הסלמות, אין workflows מורכבים
- **לא מערכת CRM** - אין ניהול לקוחות, אין היסטוריה מורכבת

## 1. סוגי משתמשים והרשאות

### 1.1 מזכירה (פותחת קריאה)

| פרמטר | ערך |
|-------|-----|
| תפקיד מערכתי | User (משתמש קצה) |
| כמות צפויה | 50-200 משתמשים |

**יכולה:**
- לפתוח קריאה חדשה דרך טופס
- למלא שדות מוגדרים
- לצפות בסטטוס הקריאות **שלה בלבד**

**אינה יכולה:**
- לערוך קריאה אחרי שליחה
- לראות קריאות של אחרים
- לבחור מטפל (אב בית)
- להתכתב או להגיב

---

### 1.2 אב בית (מטפל ראשי)

| פרמטר | ערך |
|-------|-----|
| תפקיד מערכתי | Agent (סוכן) |
| כמות צפויה | 5-20 משתמשים |

**יכול:**
- לצפות בקריאות שמשויכות אליו בלבד
- לשנות סטטוס: פתוח → בטיפול → סגור
- להעלות תמונה לאחר תיקון
- להוסיף הערה פנימית קצרה (אופציונלי)

**אינו יכול:**
- לשנות לקוח/סניף
- להעביר קריאה לאב בית אחר
- לערוך שדות הטופס
- לשלוח מיילים או להתכתב
- לנהל משתמשים

---

### 1.3 טכנאי (מטפל משני)

| פרמטר | ערך |
|-------|-----|
| תפקיד מערכתי | Agent (סוכן משני) |
| כמות צפויה | 5-15 משתמשים |

**הרשאות זהות לאב בית, עם הבדלים:**
- עובד תחת אב בית או בקבוצה שלו
- יכול לסמן "בוצע" ולהעלות תמונה
- אין לו קריאות משויכות ישירות - רואה קריאות של הקבוצה

---

### 1.4 מנהל מערכת (Admin)

| פרמטר | ערך |
|-------|-----|
| תפקיד מערכתי | Administrator |
| כמות צפויה | 2-5 משתמשים |

**יכול:**
- לצפות בכל הקריאות
- לנהל סניפים
- לנהל משתמשים
- לנהל שיוכים (סניף ↔ אב בית)
- לשנות סטטוסים
- להפיק דוחות
- לשנות הגדרות מערכת

## 2. מבנה ארגוני

### 2.1 סניף (Branch)

סניף הוא **שדה חובה בקריאה** - לא משתמש ולא קבוצה.

**מאפיינים:**
| שדה | סוג | חובה | תיאור |
|-----|-----|------|--------|
| id | מספר | כן | מזהה ייחודי |
| name | טקסט | כן | שם הסניף המלא |
| code | טקסט | כן | סמל מוסד (למשל: 343319) |
| housekeeper_id | מספר | כן | שיוך לאב בית |
| active | בוליאני | כן | האם פעיל |

**דוגמאות:**
- "גן ילדים רמה א גן 3 - 343319"
- "יסודי בית שמש - 560300"
- "תיכון הרצליה - 123456"

---

### 2.2 אב בית (Housekeeper)

**כללים:**
- אב בית יכול להיות אחראי על **כמה סניפים**
- כל סניף משויך ל**אב בית אחד בלבד**
- השיוך לקריאה מתבצע **אוטומטית** לפי הסניף שנבחר

---

### 2.3 קבוצות (Groups) - אופציונלי

קבוצה מייצגת אחריות של אב בית, לא עיר ולא סניף.

**דוגמאות:**
- "תחזוקה - יעקב"
- "תחזוקה - משה"

**שימוש:**
- ניהול פנימי
- דשבורד
- גיבוי עתידי (כשאב בית לא זמין)

> **חשוב:** המזכירה **לא רואה** קבוצות בשום שלב.

## 3. קריאה (Ticket)

### 3.1 מחזור חיים

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   פתוח      │ ──► │  בטיפול    │ ──► │ סגור/בוצע  │
│   (Open)    │     │(In Progress)│     │  (Closed)   │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 3.2 סטטוסים

| סטטוס | תיאור | מי יכול לשנות |
|-------|--------|---------------|
| פתוח (Open) | קריאה חדשה שנפתחה | מערכת (אוטומטי) |
| בטיפול (In Progress) | אב הבית התחיל לטפל | אב בית / טכנאי / מנהל |
| סגור (Closed) | הטיפול הושלם | אב בית / טכנאי / מנהל |

**אין סטטוסים נוספים** כמו: ממתין, בהסלמה, ממתין ללקוח וכו'.

---

### 3.3 שדות הקריאה

#### שדות חובה (בטופס פתיחה):

| שדה | סוג | תיאור |
|-----|-----|--------|
| branch_id | Dropdown | סניף - רשימה סגורה |
| issue_type | Dropdown | סוג תקלה - רשימה סגורה |
| description | Text | תיאור קצר של הבעיה |

#### שדות מותנים (לפי סניף או סוג תקלה):

| שדה | סוג | מתי מופיע |
|-----|-----|-----------|
| floor | Dropdown | כשהסניף הוא בניין רב-קומות |
| building | Dropdown | כשיש כמה בניינים בסניף |
| wing | Dropdown | כשיש אגפים בסניף |
| room | Text | לציון חדר/כיתה ספציפיים |

#### שדות מערכתיים (מילוי אוטומטי):

| שדה | סוג | תיאור |
|-----|-----|--------|
| id | Number | מספר קריאה ייחודי |
| created_at | DateTime | תאריך ושעת פתיחה |
| created_by | User | המזכירה שפתחה |
| housekeeper_id | User | אב הבית (שיוך אוטומטי) |
| status | Enum | סטטוס נוכחי |
| updated_at | DateTime | תאריך עדכון אחרון |
| closed_at | DateTime | תאריך סגירה |
| closed_by | User | מי סגר |

#### שדות טיפול (מילוי ע"י אב בית):

| שדה | סוג | תיאור |
|-----|-----|--------|
| completion_photo | File | תמונת הוכחת ביצוע |
| internal_note | Text | הערה פנימית (אופציונלי) |

## 6. ממשקים (Screens)

**מה רואה:**
- רשימת הקריאות שהיא פתחה

### 6.2 דשבורד אב בית

**מה רואה:**
- רשימת קריאות פתוחות/בטיפול המשויכות אליו
- מיון לפי: תאריך / סניף / סטטוס
- סה"כ קריאות פתוחות

**פעולות:**
- שינוי סטטוס
- העלאת תמונה
- הוספת הערה

**תצוגה:**
```

├─────────────────────────────────────────────────────────────┤
```

### 6.3 דשבורד מנהל

**פעולות:**

## 9. אין במערכת

הבהרה מפורשת - הפיצ'רים הבאים **לא קיימים** במערכת:

| פיצ'ר | סיבה |
|-------|-------|
| התכתבויות / Chat | לא נדרש - המערכת עובדת בסטטוסים |
| שליחת Email | לא נדרש - אין צורך בהתראות מורכבות |
| SLA / זמני תגובה | לא נדרש - המערכת פשוטה |
| הסלמות | לא נדרש - אין היררכיה מורכבת |
| העברת קריאה | לא נדרש - השיוך אוטומטי וקבוע |
| עריכת קריאה | לא נדרש - מה שנשלח, נשלח |
| עדיפויות | לא נדרש - כל קריאה חשובה באותה מידה |
| קטגוריות מורכבות | לא נדרש - סוג תקלה מספיק |

## 10. נספחים

### 10.1 מילון מונחים

| מונח | הסבר |
|------|-------|
| קריאה | בקשת תחזוקה שנפתחה |
| סניף | מוסד/בניין שצריך תחזוקה |
| אב בית | אחראי תחזוקה של סניפים |
| טכנאי | עובד תחזוקה תחת אב בית |
| סמל מוסד | קוד מזהה ייחודי של הסניף |

### 10.2 כללי עסקיים

1. **שיוך אוטומטי** - קריאה משויכת אוטומטית לפי הסניף שנבחר
2. **סניף אחד = אב בית אחד** - כל סניף משויך לאב בית יחיד
3. **אין עריכה** - קריאה שנשלחה לא ניתנת לעריכה ע"י המזכירה
4. **חובת תמונה** - מומלץ (לא חובה) להעלות תמונה בסגירה
5. **הערה פנימית** - אופציונלית, לא נראית למזכירה
