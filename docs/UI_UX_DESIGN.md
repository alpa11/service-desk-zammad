# תכנון ממשק משתמש (UI/UX)

## עקרונות עיצוב

### 1. פשטות קודמת לכל
- מינימום אלמנטים על המסך
- כפתור אחד ראשי בכל מסך
- לא יותר מ-3-4 שדות בטופס

### 2. RTL מלא
- עברית כשפה ראשית
- כל האלמנטים מיושרים לימין
- תאריכים בפורמט ישראלי

### 3. Mobile First
- עיצוב מותאם לנייד בראש ובראשונה
- כפתורים גדולים ונגישים
- גלילה מינימלית

### 4. צבעים ברורים
- סטטוסים מזוהים בצבע
- אזהרות באדום
- הצלחה בירוק

## אינטראקציות

### פתיחת קריאה - זרימה

```
1. מזכירה לוחצת "פתיחת קריאה חדשה"
2. נפתח טופס
3. בוחרת סניף מרשימה (חיפוש מהיר)
4. שדות מותנים מופיעים/נעלמים
5. בוחרת סוג תקלה
6. מזינה תיאור (מינימום 5 תווים)
7. לוחצת "שלח"
8. Spinner + "שולח..."
9. הצלחה: Toast "הקריאה נפתחה בהצלחה" + חזרה לדשבורד
10. כישלון: Toast שגיאה + שדות עם שגיאות מודגשים
```

### שינוי סטטוס - זרימה

```
1. אב בית רואה קריאה פתוחה
2. לוחץ על Radio "בטיפול"
3. הסטטוס משתנה מיידית (Optimistic UI)
4. כפתור "שמור" מופיע (או שמירה אוטומטית)
5. Toast "הסטטוס עודכן"
```

### העלאת תמונה - זרימה

```
1. אב בית לוחץ "הוסף תמונה"
2. נפתח בורר קבצים / מצלמה (בנייד)
3. בוחר תמונה
4. Preview מופיע
5. Progress bar בזמן העלאה
6. הצלחה: התמונה מופיעה בגלריה
7. כישלון: הודעת שגיאה + אפשרות לנסות שוב
```

## Responsive Design

### Breakpoints

```
Mobile:   < 640px
Tablet:   640px - 1024px
Desktop:  > 1024px
```

### שינויים לפי גודל

**Mobile:**
- Navigation הופך ל-Hamburger Menu
- כרטיסי קריאות בעמודה אחת
- כפתורי פעולה בגודל מלא
- טופס בגודל מלא

**Tablet:**
- Navigation בצד (Sidebar)
- כרטיסי קריאות ב-2 עמודות
- טופס באמצע המסך

**Desktop:**
- Navigation בצד (מורחב)
- כרטיסי קריאות ב-3 עמודות או טבלה
- טופס ב-Modal או בצד
